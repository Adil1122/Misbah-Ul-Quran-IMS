# Database schema — Misbah-ul-Quran IMS

> Generated on 2026-11-28 from the exact structure export of the live project, after migrations
> `20261126_01` … `20261127_06` (identical to `20261127_00_baseline.sql`). Regenerate when the schema changes.

**Engine:** Supabase PostgreSQL · **Schema:** `public` · **Tables:** 25 · **File storage:** private bucket `misbah-documents`

**Supabase is the only data store.** The server refuses to serve data without it, keeps nothing on its own disk,
and the browser caches no records — it loads them from the API after sign-in and saves each change through
the API (`/api/records/:collection` and the entity endpoints).

See also: [ERD.md](ERD.md) · [MIGRATIONS.md](MIGRATIONS.md) · [BACKUP_RECOVERY.md](BACKUP_RECOVERY.md)

## Conventions

| Topic | Rule |
|---|---|
| Names | Tables: plural `snake_case`. Columns: `snake_case`. Foreign keys: `<entity>_id`. |
| Primary keys | `text` ids generated by the app with a type prefix (`usr-`, `tch-`, `std-`, `cls-`, `inv-`…). Legacy rows imported from MySQL have numeric-string ids (`'1'`, `'119'`). Public-content tables (`news`, `slider_images`, `prayer_timings`) use `integer` ids with no default — the app supplies them. |
| Timestamps | `created_at` / `updated_at` `timestamptz` (UTC). `updated_at` is maintained by the shared `set_updated_at()` trigger. |
| Enumerations | `text` + `CHECK` constraint (no Postgres ENUM types). Checks are case-insensitive; each table keeps the casing the app already writes. |
| Deletes | Campus → `RESTRICT`. Student → `RESTRICT` (the app archives instead). Teacher user with history → `RESTRICT` (the app deactivates instead). Actor columns on log tables → `SET NULL`. |
| JSON | Structured values use `jsonb` (`students.*_contact_details`, `audit_logs.details`, `teacher_profiles.assigned_class_ids`). |
| Credentials | Never stored in `public`. Supabase Auth only. |

## Access model (Row Level Security)

RLS is enabled on every table. The Express server uses the service-role key and enforces the same rules in code.

| Role | Access |
|---|---|
| `anon` (not signed in) | Read `campuses`, `news`, `slider_images`, `prayer_timings`. Nothing else. No writes. |
| SUPER_ADMIN | Everything. |
| CAMPUS_ADMIN | All rows of the campuses in `user_campus_access`. |
| TEACHER | Read their campus's students, classes and colleagues; manage attendance of their own classes; insert incidents/medical records; read own attendance. |
| PARENT | Read their own children's student rows, classes, attendance and invoices. |

Helper functions (all `SECURITY DEFINER`, `search_path = ''`): `app_current_user_id()`, `app_current_role()`, `app_has_campus(campus)`, `app_is_admin_for(campus)`, `app_is_staff_for(campus)`, `app_is_teacher_of_class(class)`, `app_is_parent_of(student)`, `app_shares_campus_with(user)`.

## Known technical debt

- **Pending teacher approvals** have no data source: nothing in the app creates them, so the list is always empty.
- `users.allowed_campus_ids` and `teacher_profiles.assigned_class_ids` are legacy duplicates of `user_campus_access` and `classes.teacher_id`; remove once no code reads them.
- `classes.title` duplicates `name`.
- `users.status` is an integer (1 = active, 0 = inactive).
- `payment_invoices.reference_id` and `documents.(type, reference_id)` are polymorphic references without FKs.
- The 3 `documents` rows imported from MySQL have no file in Storage (their files were never migrated).
